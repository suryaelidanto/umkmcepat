# Security Hardening (Deep Audit Findings) — Design

**Date:** 2026-08-06
**Status:** Draft — plan open (`docs/superpowers/plans/2026-08-06-security-hardening.md`)
**Source:** Four-pass security audit (IDOR/ownership, secrets, auth/session, payments, uploads, headers/CORS, generated-code execution, CI/CD, XSS, moderation, rate limiting, infra exposure, error leakage). Full list lives in the audit conversation; this spec covers the items this plan will actually fix.

## Goal

Close the audit findings that are real, exploitable-now, or one-line cheap fixes: the preview-iframe sandbox bypass (CRITICAL), the spoofable rate-limit client IP (CRITICAL), the hardcoded temp-image signing secret (MEDIUM), the disconnected Turnstile CAPTCHA (MEDIUM), the raw internal error messages leaked to clients (MEDIUM), the misleading CORS comment on preview proxy responses (MEDIUM), and CI secret/action hygiene (LOW). Everything else from the audit is explicitly out of scope (see Out of Scope).

## Why

Seven findings, three tiers of urgency:

1. **CRITICAL — preview iframe same-origin.** The workspace preview iframe (`WorkspacePrimitives.tsx`) is served from a same-origin URL (`/api/projects/<id>/preview/`) but carries `sandbox="allow-scripts allow-same-origin allow-forms"`, and the enforced CSP for that route (`security-headers.ts` privatePreview branch) also contains `sandbox allow-scripts allow-same-origin`. `allow-same-origin` + same-origin `src` means the browser does NOT give the iframe an opaque origin: generated (AI-authored, arbitrary) JS runs with the real app origin, can `fetch('/api/...')` with the viewer's session cookie auto-attached, and those requests are genuinely same-origin so the `Origin`/`Sec-Fetch-Site` CSRF gate passes legitimately. Chain with the admin-observer feature (admins can open any user's project preview): malicious project content shown to an admin = attacker-controlled JS running with admin's session against the full authenticated API. The code's own comment claims the iframe is cross-origin; the shipped attribute contradicts it. The fix direction is what the code already believes is true: remove `allow-same-origin` from both the iframe attribute and the CSP.

2. **CRITICAL — spoofable rate-limit IP.** `getClientIp()` (`src/lib/rate-limit.ts`) trusts `x-forwarded-for`'s FIRST entry, which is client-controlled. Behind Cloudflare the chain is `<spoofed>, <real-client>` — `split(",")[0]` is the attacker's own value. Every IP-keyed bucket (global 300/min, AI 20/10min, build 5/h) is bypassable by rotating the header. `cf-connecting-ip` (the authoritative, proxy-set header) is never read. Blast radius: unlimited AI-generation calls (per-call API cost) and build attempts per IP; per-user limits still bind authenticated users, but unauthenticated abuse is unbounded.

3. **MEDIUM — hardcoded temp-image signing secret.** `temp-image-token.ts` signs with `BETTER_AUTH_SECRET || AUTH_SECRET || "dev-secret"`. Verified against `@auth/core`'s `setEnvDefaults` source: it only READS `AUTH_SECRET` into the config object, never writes it back into `process.env`, and nothing in this app sets either var (the real secret is `NEXTAUTH_SECRET`). So the HMAC key is the public string `"dev-secret"` in every environment. Forged tokens can bypass the 1-hour TTL and tamper `sizeBytes`/`contentType` claims; cross-user file reads are still blocked by the separate session-derived `userId` + key-prefix checks, which is why this is MEDIUM not CRITICAL. The signature is nonetheless meaningless and the secret is a leftover from a better-auth migration.

4. **MEDIUM — Turnstile not enforced server-side.** The client calls `/api/auth/turnstile`, then separately POSTs to Auth.js's `/api/auth/signin/google`; nothing server-side links the two. A scripted POST straight to the signin endpoint skips Turnstile entirely (CSRF token is freely obtainable from `/api/auth/csrf`). Any bot-abuse protection the CAPTCHA was meant to provide does not exist. Fix: server-side gate on the signin initiation path via a short-lived HMAC-signed HttpOnly cookie issued by the verified `/api/auth/turnstile` endpoint.

5. **MEDIUM — raw internal error messages to clients.** Six catch blocks return `error.message` verbatim: `api.uploads.temp-images.ts` (S3/MinIO hostnames), `api.support.tickets.ts`, `api.support.tickets.$ticketId.ts`, `api.support.tickets.$ticketId.resolve.ts`, `api.admin.tickets.$ticketId.reply.ts`, `api.admin.tickets.$ticketId.resolve.ts` (Prisma codes, Resend errors), plus `api.projects.$id.generate.ts` which publishes the raw message as SSE `detail` rendered verbatim into the build-progress UI (Redis/BullMQ hostnames). `mapToUserFacingError` exists and is used correctly elsewhere; these sites just never got wired.

6. **MEDIUM — misleading CORS comment on preview proxy responses.** `runtime-proxy.ts` sets `Access-Control-Allow-Origin: *` on every preview/asset/publish response with a comment claiming it is "overwritten later by applySecurityHeaders" — false; `applySecurityHeaders` never touches CORS. Not exploitable today (nothing sets `Access-Control-Allow-Credentials: true`), but the comment actively misleads the next dev who adds a credentialed cross-origin route. The `*` itself is load-bearing for the sandboxed opaque-origin preview iframe (opaque-origin subresource `fetch` requires ACAO) and must stay — only the comment changes.

7. **LOW — CI hygiene.** `deploy.yml` inlines `secrets.DEPLOY_PATH` into the SSH script text instead of passing it via the action's `envs:` mechanism (inconsistent with `APP_IMAGE_TAG` on the same step); `quality.yml` pins actions to mutable version tags (`actions/checkout@v5`, `oven-sh/setup-bun@v2`) while `deploy.yml` correctly SHA-pins everything.

## Decisions (locked)

1. **Sandbox first, CORS second.** Remove `allow-same-origin` from BOTH the iframe `sandbox` attribute and the privatePreview CSP directive. The parent's `handleMessage` already validates ready/annotation messages by `event.data.type` only (no origin check), so the opaque-origin bridge keeps working. `<img>`/`<script>`/`<link>` loads are not CORS-restricted and keep working. Generated apps are static frontends with no server-side fetch surface; any future runtime `fetch` from generated JS is served by the preview proxy which keeps `Access-Control-Allow-Origin: *` (safe with opaque origin, no credentials). If the E2E preview check shows a broken asset or signal, the fallback decision is documented in Task 1 (do NOT re-add `allow-same-origin`; fix the asset path instead).
2. **Client IP resolution order.** `cf-connecting-ip` (trusted, proxy-set, overwrites client-supplied) → last entry of `x-forwarded-for` (the trusted-proxy-appended hop; attacker-supplied leading hops are ignored) → `x-real-ip` → `127.0.0.1`. Every candidate passes a plausibility check (≤45 chars, `[0-9a-fA-F:.]` only) before being used as a bucket key. `getClientIp` becomes exported for direct unit testing.
3. **Temp-image secret.** Use `NEXTAUTH_SECRET || AUTH_SECRET`; if neither is set in production, THROW (fail closed, mirroring `preview-asset-token.ts:110-114`); in dev keep the `"dev-secret"` fallback so local flows keep working. No new env vars — `NEXTAUTH_SECRET` already exists and is required in production by `production-config.ts`.
4. **Turnstile server-side gate.** `/api/auth/turnstile` on success issues `umkm_turnstile_verified` — HMAC-signed (`v1.<issuedAtMs36>.<nonce>.<sig>`), `HttpOnly`, `SameSite=Lax`, `Secure` when `NEXTAUTH_URL` is https, `Max-Age=600` (10 min). The `/api/auth/$` POST handler rejects `/api/auth/signin/<provider>` (signin initiation only — NOT the OAuth callback, which is a redirect back from Google and is where the CSRF gate already applies) with 403 unless the cookie verifies within the grace window. Not single-use by design: a bot that solves one challenge can reuse it for 10 minutes, which is acceptable (Turnstile's job is to make scripted signups expensive, not impossible) and avoids stateful single-use tracking. Client flow (`LoginConsentDialog`) is unchanged: it already calls `/api/auth/turnstile` before `signIn`, and the cookie rides along on the same-origin POST automatically.
5. **Error messages.** Route all seven sites through `mapToUserFacingError`; log the raw error server-side (`console.error`) at each site. Extend `KNOWN` with the benign temp-image upload messages so users keep seeing the exact size/format guidance instead of the generic fallback (they are stable Indonesian strings, safe to round-trip).
6. **CORS.** Keep `Access-Control-Allow-Origin: *` on preview proxy responses; replace the false "overwritten later" comment with the real rationale. Add a repo-wide negative check that no response path sets `Access-Control-Allow-Credentials: true`.
7. **CI.** `DEPLOY_PATH` moves into the `envs:` list + `env:` block of the ssh-action step; `quality.yml` pins `actions/checkout` to `08c6903cd8c0fde910a37f88322edcfb5dd907a8` (v5.0.0) and `oven-sh/setup-bun` to `0c5077e51419868618aeaa5fe8019c62421857d6` (v2.2.0) with version comments, matching `deploy.yml`'s existing style.

## Acceptance criteria

1. `applySecurityHeaders` privatePreview CSP = `sandbox allow-scripts; frame-ancestors 'self'; object-src 'none'; base-uri 'none'`; iframe attribute = `sandbox="allow-scripts allow-forms"`; existing tests updated and passing.
2. A workspace preview of a generated project still loads: ready signal arrives, annotation/edit bridges respond, images render (verified via `bun run dev` + a generated project, and `scripts/e2e-build-smoke.sh` if runnable locally).
3. `getClientIp` returns `cf-connecting-ip` when present; otherwise the LAST `x-forwarded-for` entry; ignores leading spoofed hops; falls back to `x-real-ip` then `127.0.0.1`; rejects garbage. Unit tests cover all five branches.
4. Temp-image tokens sign with `NEXTAUTH_SECRET` when set; `signTempImageToken`/`verifyTempImageToken` round-trip with an explicit secret; production without any secret throws; dev fallback still works.
5. `POST /api/auth/signin/google` returns 403 without a valid `umkm_turnstile_verified` cookie, and passes it through to Auth.js with one. `GET` and non-signin POST paths (`/api/auth/session`, `/api/auth/callback/*`) are unaffected. `/api/auth/turnstile` success sets the cookie; existing route tests updated.
6. None of the seven error sites return raw `error.message`; known temp-image messages still reach users verbatim; unknown internals get the generic Indonesian fallback; raw messages only in server logs.
7. `runtime-proxy.ts` comment states the true CORS intent; `grep -ri "access-control-allow-credentials" src/` returns zero hits.
8. `deploy.yml` passes `DEPLOY_PATH` via `envs:`/`env:`; `quality.yml` actions pinned to the SHAs above. `bun run check` green; `bun run verify` green before push.

## Out of scope (deferred, tracked)

- **JWT session revocation** (audit finding: logout doesn't invalidate; dead `RefreshToken` system): requires a product decision (DB sessions vs. wiring `revokeAllSessions` into logout/ban); separate plan.
- **Unsandboxed generated build execution**: already inert in production (hard preflight throw); work belongs to the isolated-executor infra effort, not a code fix.
- **Publish-time content re-scan + jailbreak-aware moderation**: product decision on moderation policy; separate plan.
- **`frame-ancestors` on `/p/*`**: confirm product intent (published sites embeddable anywhere?) before adding.
- **Dependency CVEs** (`fast-uri`, `brace-expansion`, both build-tooling-only): optional `bun update`, not part of this plan.
- **Cloudflare Zero Trust ingress verification** (9router/headroom have no app-level auth): operational dashboard check, not code.
