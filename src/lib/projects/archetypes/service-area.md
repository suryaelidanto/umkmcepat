# Archetype: service-area (plumber / cleaning / salon / laundry — area-bound service)

## matches

- tukang ledeng, jasa bersih, salon, laundry, jasa servis panggilan
- any on-site or area-bound service whose coverage radius is the headline

## recommended_sections

- Coverage area — the map or kelurahan list answers "is my address in range?" before anything else; out-of-area visitors bounce.
- Service list — what the provider actually does, scoped (e.g. "servis AC 1/2 - 2 PK", not "segala perbaikan").
- Booking-intent CTA — WA with the address pre-filled; the transaction starts as a lead, not a checkout.
- Operating hours + response window — when the provider picks up the phone and how soon they arrive.

## avoid_sections

- Generic testimoni carousel — trust comes from coverage + service scope, not fabricated praise.
- 3-feature value grid — "Cepat, Rapi, Bergaransi" says nothing about the actual trade.
- Pricing table before coverage — price is moot if the address is out of range.

## page_count

- landing: one page. `marketing_site` only if multiple service verticals (e.g. AC + fridge + laundry machines) each warrant a detail page.

## cta_logic

- Primary: "Booking via WA" with address + service pre-filled. Secondary: "Cek apakah lokasi saya terjangkau" only when the coverage area is genuinely uncertain from the list alone.

## visual_hooks

- A map tile or kelurahan chips, not an abstract hero gradient — coverage is the product.
- Trade-specific iconography (wrench, spray bottle, washing machine) on the service list, not generic checkmarks.
- Response-time badge ("Hari ini sampai") near the CTA, not buried in body copy.

## example_structure

Header (name + response window) → Coverage area (map or kelurahan chips) → Service list (scoped items) → Hours → Booking CTA. Depart when justified — a salon with a physical location may swap coverage for a seat-map and walk-in hours.
