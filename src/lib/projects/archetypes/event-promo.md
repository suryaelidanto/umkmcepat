# Archetype: event-promo (bazaar / pop-up / event)

## matches

- bazaar, pop-up market, acara, festival, konser, workshop satu kali
- any time-bound event whose value is the date + lineup

## recommended_sections

- Event date + time — the single most important fact; it gates every decision and must be above the fold.
- Lineup / vendors / agenda — what is happening and who is there; the program is the product.
- Location + how to get there — venue, map, and transport notes; attendees navigate before buying.
- Register / buy ticket CTA — the path to commit; the transaction is a seat or slot, not a product.

## avoid_sections

- Generic 3-feature grid — "Seru, Ramai, Berkesan" says nothing about this event.
- Testimoni carousel — for a first-run event there are no past attendees to quote; fabricating them reads as fraud.
- Vague "coming soon" — a dateless event page fails its only job; if the date is unconfirmed, say so explicitly.

## page_count

- landing: one page. `marketing_site` only when the event has multiple stages/tracks (e.g. a festival with a music stage + workshop stage) each needing a detail page.

## cta_logic

- Primary: "Daftar" or "Beli tiket" opening registration or checkout. Secondary: "Pengajuan booth" only when the event has a vendor call.

## visual_hooks

- Date-forward hero: the date as the largest type, not a gradient — the date is the headline.
- Lineup list with named performers/vendors + time slots, not a generic "banyak cabang" claim.
- Venue map or address card with transport notes, not an abstract location pin.

## example_structure

Header (event name + date badge) → Date + time + venue → Lineup / agenda → Register / buy ticket CTA. Depart when justified — a festival with multiple stages may add a per-stage schedule before the CTA.
