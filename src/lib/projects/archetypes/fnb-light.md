# Archetype: fnb-light (kue / snack / catering — small product list)

## matches

- penjual kue, jajanan, snack, katering kecil, Catering Rumahan
- any F&B whose product is a small fixed catalog rather than a changing menu

## recommended_sections

- Product showcase — a tight catalog (5-12 items) is the product; each item needs photo + name + price.
- Pickup / delivery — make the fulfillment path explicit; this is the buyer's first logistics question.
- Order CTA — WhatsApp pre-order or DM; the path to buy should be one tap.
- Lead time — kue/catering usually needs advance notice; stating it filters out same-day asks.

## avoid_sections

- Full menu board — too heavy for a handful of products; a menu board implies changing daily items.
- Reservation CTA — no table to reserve; this is product, not seating.
- Generic hero tagline — "Enak, Sehat, Murah" describes nothing about the actual product.

## page_count

- landing: one page. `marketing_site` only if a separate gallery or paket page has a distinct purpose the home cannot serve.

## cta_logic

- Primary: "Pesan via WA" with the item name pre-filled. Secondary: pre-order form only when lead time varies per product.

## visual_hooks

- Product-first grid: each item photographed against a clean surface, not a lifestyle backdrop.
- Pickup/delivery badges visible on each card, not buried in a footer.
- Sticky order button on mobile — the buy decision is made while scanning products.

## example_structure

Header (name + area) → Product grid (photo + name + price + pickup/delivery badge) → Lead time → Order CTA. Depart when justified — a catering business may swap the grid for a paket list with pax + price.
