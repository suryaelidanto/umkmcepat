# Archetype: property-rental (kos / sewa properti)

## matches

- kos, kontrakan, apartemen sewa, ruko sewa, villa sewa harian
- any rental whose value is a unit + price + location

## recommended_sections

- Available units — the rooms/units are the product; cards with photo + size + price are the headline.
- Price per period — monthly/daily/weekly rent legible on every unit; the shopper filters by budget first.
- Location + access — address, map, and nearby landmarks (station, campus, office area); "dekat dengan…" is the decision.
- Availability inquiry CTA — the lead starts as "is this unit still free?", not a checkout.

## avoid_sections

- Generic 3-feature grid — "Strategis, Nyaman, Terjangkau" says nothing about the actual units.
- Testimoni carousel — avoid unless real tenants attribute quotes; rental trust comes from clear pricing + photos.
- Long about-the-owner section — the units + price are the trust signals, not the owner's biography.

## page_count

- landing: one page. `marketing_site` only when the property runs multiple unit types (kos harian vs bulanan, villa variants) each needing a detail page.

## cta_logic

- Primary: "Tanya ketersediaan" via WA with the unit pre-filled. Secondary: "Pesan langsung" only when a daily-rental property has real online booking.

## visual_hooks

- Unit cards with photo + size + price, not a single hero photo of one room.
- A map tile or "X menit ke [landmark]" chips — access is the decision, not the chrome.
- Availability badge ("Tersedia" / "Penuh") on each card, not in body copy.

## example_structure

Header (name + location chip) → Available units (cards: photo + size + price + availability) → Location + access → Inquiry CTA ("Tanya ketersediaan"). Depart when justified — a villa may add a per-night calendar before the inquiry CTA.
